Why Clean Data Beats a Bigger Model

By Tabish Syed • 2 mins read
Scroll

When a model performs badly, the first idea is often to use a bigger one. In practice the problem is more often the data. Better data usually improves results more than a bigger model does.

What “dirty” data looks like

Missing values, duplicate rows, typos like “Mumbai” and “Mumbay”, numbers in different units, and labels that don’t match the example. A model learns from all of it, mistakes included.

Garbage in, garbage out

A model finds patterns in whatever you give it. If a quarter of your labels are wrong, it will learn some wrong patterns and then repeat them confidently. A larger model can even memorize the errors, which makes the results look good in training and fail in real use.

What to check first

Look for duplicates and missing values. Make sure the same thing is written the same way everywhere. Read a random sample of your labels by hand. Check that the classes are balanced, so one category doesn’t make up almost the whole dataset.

A common trap: data leakage

If the same example shows up in both the training set and the test set, your accuracy score is too high. The model looks great on paper and then disappoints on new data. Split the data before you clean or transform it.

Where to spend your time

In the plant disease classifier I built, improving the images before training mattered. Steps like noise reduction and thresholding helped the model focus on the infected area of the leaf. Preparing the data this way is slower than picking a bigger network, but it pays off.

Before you scale up the model, scale up the quality of the data.
